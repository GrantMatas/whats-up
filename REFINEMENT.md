# Refinement audit and acceptance

The September 30 desktop baseline ran against real Fishers sources. 68 sources, 11 records, 8 mapped records, 8 Radar matches; no renderer errors. Screenshots of Overview, Discover, Map, Radar, Reports, Sources, Settings and detail are in artifacts/baseline. The first runner stalled under Windows occlusion; disabling renderer background throttling for the isolated test resolved it.

The existing neutral/rust design uses Segoe UI, Lucide, MapLibre and CSS tokens. Large repeated rounded cards, illustrative event art and oversized generic headings consume space. Refine toward an editorial field guide: real headlines, flat divided rows, compact navigation, integrated maps and charts, inspectable research panels. Preserve light/dark, keyboard states and reduced motion.

Existing discovery: Wikimedia public directories, verified nearby institutions, NWS alerts, advertised feeds and same-domain links to depth two. Extraction: RSS/Atom, JSON-LD, ICS, public JSON and conservative HTML. Three fetch jobs, one per domain, robots checks, conditional caches and a protected one-window browser fallback. Discovery refresh uses last scan rather than a separate research cadence. Source-type confidence caps have no evidence breakdown. The minute scheduler only checks due feeds while the app runs. Onboarding/settings exist; reset currently deletes everything.

Acceptance proceeds through seven milestones: (1) authored visual refinement, visible scans/history/daily schedule; (2) interchangeable search providers, query/cache expansion and bounded result exploration; (3) public posts, evidence, explainable confidence and conflicts; (4) timeline/calendar/changes/topics/collections; (5) observed pulse/coverage/trending/relationships/history; (6) tour/reset/commands/personalization/watch areas; (7) queue/security/accessibility/real-data/packaged visual QA. No fabricated results or historical comparisons; provider restrictions remain visible.

Automatic scans run while the desktop app is open, with a catch-up scan on launch. Google is an explicit user-driven browser path, never an automated protected-page scraper. A configured SearXNG endpoint uses its documented JSON search API (https://docs.searxng.org/dev/search_api.html); unavailable providers must fail independently.

All seven milestones are implemented. Independent bounded queues and scoped persistence now retain original evidence, confidence factors, conflicts/cancellations, scan tasks, meaningful changes, publisher checks, relationships, coverage and daily observed activity. Smart cadence is independent of frequent lightweight checks. Mwmbl results and public-source ingestion were exercised in a real Fishers run; unavailable Bluesky search returned a recorded HTTP 403.

The renderer includes the eight exploration modes, source catalog filters/check history, scan overlay/history, tutorial, commands, watch areas and personalization. Publisher images from structured event metadata, feeds, JSON, ICS attachments and scoped event-page markup flow through a bounded public image loader. Missing, blocked or failed images retain category placeholders. No images or records are generated to populate screens.

Validation: 81 tests / 13 files passed; production type check/build and Windows packaging passed. Native real-data checks verified light/dark primary and exploration screens, tutorial, feedback/watch-area persistence, source checks and both reset paths. The final packaged run additionally checks publisher images and failed-asset fallback. Reports and screenshots remain in `artifacts/real-smoke/`; `QA.md` records limits and baseline evidence.
